# 第九篇：撤销重做与快捷键——编辑器的"后悔药"

**核心要点：**

- 两条实现路线：快照式（整份 Schema 存档，简单粗暴）vs 命令式（do/undo 对称操作，省内存但复杂）的取舍
- 历史栈设计：undo/redo 指针、容量上限、内存占用估算
- 合并与事务：连续输入合并（coalescing）、一次拖拽 = 一个事务（拖拽结束才入栈）、分支历史的处理策略
- 快捷键体系：键位表设计、与浏览器/输入法冲突处理、命令面板（Cmd+K）的命令注册模型
- 剪贴板：内部 Schema 复制粘贴、剪贴板数据的安全与版本兼容、跨页面粘贴的降级
- 一切编辑操作命令化：为协同编辑（第十五篇）提前铺路

**这篇适合谁看：**

- 正在做编辑器、需要实现 Undo/Redo 的同学
- 历史记录"能撤销但撤销粒度乱七八糟"的团队
- 想为后续协同编辑打基础的架构师

- 命令模式类图（Command / History / Invoker）
- 历史栈合并（coalescing）示意图
- 快照式 vs 命令式的内存与实现复杂度对比表
