# 第十二篇：性能专题——千级节点的画布如何保持 60fps

**核心要点：**

- 瓶颈画像：节点数 × 交互频率，拖拽时的 reflow 灾难与布局抖动（layout thrashing）
- 基本功：transform 替代 top/left、rAF 合帧、will-change 与合成层、避免强制同步布局
- 选中/悬停框的实现代价：全局单实例 hover 框 vs 逐节点注入边框的性能差异
- 渲染升级路线一：DOM + 虚拟化/按需渲染——视口外不渲染、进入视口再挂载
- 渲染升级路线二：OffscreenCanvas + Worker 化渲染——把渲染循环搬出主线程，与虚拟化可叠加，Figma 路线的地基
- 渲染升级路线三：Canvas/WebGL（Konva/Pixi）——自绘的收益与代价（事件系统、a11y、DOM 生态全都要自己造）
- 性能度量方法：Performance 面板看拖拽帧、Long Task 分析、建立性能回归基线

**这篇适合谁看：**

- 画布"节点一多就卡"的同学
- 在 DOM 和 Canvas 方案之间摇摆的技术负责人
- 需要建立编辑器性能基线的团队
