# 第十篇：低代码编辑器架构（上）——画布、物料与 Schema 协议

**核心要点：**

- 标准三栏形态：物料区 + 画布 + 属性面板，各区域职责边界与依赖方向
- 单一数据源原则：Schema 是唯一真相，物料区、画布、属性面板都是 Schema 的投影
- Schema 协议设计：组件树（嵌套结构）、属性、样式、事件、数据绑定五大块，参考阿里 lowcode-engine 协议
- 画布布局模式：栅格布局 vs 自由布局 vs 流式布局——数据结构、交互方式与适用场景的差异
- Schema 校验：JSON Schema 与 Zod 两类方案，设计期强校验与运行期兜底的分工
- 版本化与兼容：Schema 升级、迁移函数、脏数据兜底
- 状态管理选型：编辑器为什么常用 zustand/自研 store 而非 redux——细粒度更新与画布性能的关系
- 画布与属性面板的双向流：选中 → 表单回填 → 修改 → Schema 更新 → 画布重渲染

**这篇适合谁看：**

- 从零搭建低代码/搭建平台的负责人和核心开发
- Schema 设计"越加越乱"、想重新梳理协议的团队
- 想看懂 lowcode-engine 等开源方案设计思路的同学
