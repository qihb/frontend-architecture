# 第十五篇：走向生产——协同编辑、插件体系与工程化交付

**核心要点：**

- 协同编辑演进：悲观锁 → OT → CRDT（Yjs）的思路差异，编辑器场景为什么 CRDT 渐成主流
- Yjs 落地要点：Y.Map/Y.Array 建模 Schema、awareness 与远程光标、与 Undo（第九篇）的整合
- Provider 选型：y-websocket 自建、y-indexeddb 本地持久化、Liveblocks/PartyKit 类托管服务——离线优先与实时协同的取舍
- 编辑器微内核架构：命令、钩子、面板三大扩展点，插件的生命周期与依赖管理
- 工程化闭环：拖拽交互的 Playwright 自动化测试（模拟拖拽的稳定性）、Schema 版本迁移、编辑器与产物的灰度发布
- 工程组织：Monorepo 管理设计器、渲染器与物料，物料的独立构建与版本发布，编辑器以 SDK 形式嵌入存量系统
- 全系列收束：一张架构决策清单——场景复杂度 × 团队规模 × 性能要求，回答"我的场景该用哪种方案"
- 演进建议路线图：从引入一个拖拽库，到画布，到完整搭建平台的分阶段建设

**这篇适合谁看：**

- 正在或即将负责搭建平台/编辑器架构的工程师与架构师
- 有多人协作诉求、在评估协同方案的技术负责人
- 想把编辑器从"能 Demo"推进到"能上生产"的团队
