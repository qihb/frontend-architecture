# 前端可视化拖拽——从入门到架构实战

本专栏从浏览器拖拽的底层事件机制出发，经过手写排序列表与看板的实战训练，进入 Figma 式画布的坐标数学、命中检测、对齐吸附与撤销重做，最终落到低代码编辑器的 Schema 协议、渲染引擎、性能优化、流程图与表单设计器、协同/插件等生产化话题，帮助读者从"会用拖拽"成长为"能做编辑器架构"。

## 专栏定位

- **正文（第 1–15 篇）**：四个阶段递进——入门篇（场景与事件原理）、进阶篇（画布数学与交互手感）、架构篇（低代码编辑器）、高阶篇（流程图、表单与生产化）
- **番外篇（4 篇）**：移动端拖拽、可访问性、AI + 可视化搭建、性能事故排查
- **配套案例（5 个，规划中）**：可运行的手写拖拽、看板、迷你编辑器、流程图与表单设计器示例

- [第二篇：拖拽的底层机制——鼠标事件、Pointer Events 与 HTML5 DnD API](02-drag-events-mechanism.md)
  - 三代 API 演进：mouse/touch 事件 → Pointer Events（统一指针）→ HTML5 DnD（draggable/dataTransfer）
  - HTML5 DnD 完整事件生命周期，事件在"拖拽源"与"放置目标"之间如何流动
  - 原生 DnD 的硬伤：拖拽影像不可定制、移动端不支持、默认样式难看
  - 为什么 Figma、Miro 等专业画布都绕开原生 DnD 自己实现
  - Pointer Events 关键细节：pointerId、setPointerCapture、touch-action 与 preventDefault 的坑
  - 建议配图：事件生命周期时序图 + "原生 DnD vs 手写事件"对比表

- [第三篇：主流拖拽库选型——dnd-kit、react-dnd、SortableJS、Interact.js 怎么选](03-drag-libraries-comparison.md)
  - 四库定位：SortableJS（DOM 排序专家）、react-dnd（拖拽状态机抽象）、dnd-kit（现代 React 方案、传感器架构）、Interact.js（指针交互全能）
  - 原理差异：直接操作 DOM vs 状态机驱动 vs Sensor 抽象层
  - 选型决策树：技术栈（React/Vue/框架无关）× 场景（排序/看板/自由拖拽）× a11y 与体积要求
  - Vue 生态补充：vue-draggable-plus、useSortable
  - 建议配图：选型决策树 + 四库能力对比矩阵

- [第四篇：手写实战（一）——从零实现一个拖拽排序列表](04-handwritten-sortable-list.md)
  - 最小可用拖拽 = mousedown + mousemove + mouseup 的状态机
  - 三件套：拖拽影像（ghost/clone）、占位符（placeholder）、目标位置判定
  - FLIP 动画原理：First-Last-Invert-Play，为什么排序动画不能直接用 transition
  - 手感细节：拖拽句柄、rAF 节流、快速甩动与拖出容器的边界处理
  - 建议配图：拖拽状态机图 + FLIP 动画四步分解图

- [第五篇：手写实战（二）——看板与跨容器拖拽](05-kanban-cross-container.md)

  - 碰撞判定策略对比：指针进入、矩形相交、最近中心（closest center）——dnd-kit 的核心思想

## 阅读建议

- 如果你是拖拽新手，建议从第一篇按顺序阅读，第 2–5 篇是动手写代码的核心基础
- 如果你用过拖拽库但"手感"总差一口气，直接看第六至九篇（坐标、命中、吸附、Undo）
- 如果你正在搭建低代码/搭建平台，重点看第十至十二篇（Schema 协议、渲染引擎、性能）
- 流程图、表单与协同是相对独立的专题，可按需选读第十三至十五篇与番外篇
