# 番外篇二：拖拽的可访问性——键盘拖拽与屏幕阅读器

**核心要点：**

- 拖拽为什么天然排斥键盘与读屏用户：鼠标依赖、缺乏语义、状态不可感知
- 键盘拖拽的设计：Space 抓起、方向键移动、Space 放下的交互协议，与排序/移动两类场景的映射
- ARIA 语义：draggable 的 aria 属性表达、"抓起/移动中/放下"的 live region 播报
- 权威参考：WAI-ARIA Authoring Practices 的拖拽交互模式——注意 aria-grabbed/aria-dropeffect 已被废弃，用 live region 播报代替
- dnd-kit 的 a11y 实践：内置键盘传感器与屏幕阅读器公告的实现思路
- 往返验证：只用 Tab + 方向键完成一次看板卡片移动的完整路径设计
- 可访问性与体验的平衡：键盘拖拽不能拖慢鼠标用户，快捷键分层与焦点管理

**这篇适合谁看：**

- 关注无障碍合规（政务、出海产品）的团队
- 想让编辑器/看板支持键盘操作的前端
- 对 dnd-kit a11y 设计感兴趣的同学
