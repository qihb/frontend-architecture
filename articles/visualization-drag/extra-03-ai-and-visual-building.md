# 番外篇三：AI + 可视化搭建——自然语言生成 Schema、AI 智能布局与 Copilot

**核心要点：**

- 为什么低代码平台是 AI 的天然盟友：Schema 是结构化、可校验、可生成的"中间语言"
- 自然语言 → Schema：LLM 生成页面描述的约束设计（JSON Schema 校验、物料白名单、多轮修正）
- 多模态入口：截图 → Schema——设计稿/竞品页面直出结构化 Schema，与自然语言入口互补
- 外部竞争与融合：v0、Bolt.new、Lovable 类"AI 直接生页"产品对传统低代码的冲击——生成门槛被打平后，低代码平台的价值向治理、集成、私有物料生态迁移
- Agent 化编辑器：AI Agent 通过工具调用/MCP 直接操作编辑器（增删组件、调属性、预览验证）——把编辑器能力封装成"Agent 可调用的工具"是 2026 年的新趋势
- AI 智能布局：拖拽放置时的智能对齐建议、栅格填充、基于现有页面的风格延续
- 编辑器 Copilot 的交互形态：对话式生成、选中元素的语义操作、"说一句改一句"的修订流
- 工程化考量：生成的 Schema 如何进入既有校验/发布流程、人工确认边界、成本与延迟控制
- 与主专栏呼应：AI 不改变编辑器架构，但会让"Schema 协议设计"（第十篇）的价值被放大

**这篇适合谁看：**

- 在低代码平台中规划 AI 能力的产品与工程师
- 想了解"AI 生成页面"到底生成的是什么的技术同学
- 关注大模型在垂直工程场景落地的架构师
