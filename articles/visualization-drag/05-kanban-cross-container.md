# 第五篇：手写实战（二）——看板与跨容器拖拽

**核心要点：**

- 跨容器拖拽的状态模型：源列表 / 目标列表 / 拖拽项三元组，以及"移出即改数据"的时机问题
- 碰撞判定策略对比：指针进入（pointer within）、矩形相交（rect intersection）、最近中心（closest center）——dnd-kit 的核心思想与各自的坑
- 嵌套容器的判定优先级：子容器优先、droppable 边界、禁用区与空列表的处理
- 自动滚动（auto-scroll）：边缘触发、速度曲线、拖拽影像跟随滚动容器的补偿计算
- 看板数据结构与 UI 同步：先改数据再渲染，避免 DOM 和状态"各说各话"
- 代码落地：在第四篇基础上扩展出多列看板，支持跨列移动与自动滚动

**这篇适合谁看：**

- 做过简单拖拽、现在要做看板/多容器需求的同学
- 想理解 dnd-kit 碰撞判定设计的工程师
- 被跨容器拖拽的"闪烁、跳动、错位"折磨过的同学

**配图计划：**

- 三种碰撞判定策略示意图（同一场景下的判定结果差异）
- 跨容器拖拽的数据流图（状态三元组 + 同步时序）
- 自动滚动触发区域与速度曲线示意图
