# 第十二篇：微前端测试与联调策略——主子应用如何稳定协作

**核心要点：**

- 测试分层：子应用独立测试（保留原有单测/组件测试体系）→ 集成测试（主子契约与切换链路）→ 端到端测试（关键业务路径全链路），每层目标不同、成本不同
- 契约测试是核心：props 协议、全局状态结构、通信事件清单做 Schema 化校验，主任一方改动破坏契约时在 CI 就报错，而不是等联调炸锅
- 主子联调工程方案：本地代理映射线上 entry（只起主应用改子应用）、子应用独立调试模式（脱离主应用裸跑）、fake 子应用桩（子应用未就绪时主应用先行开发）
- 集成环境策略：为集成测试专门部署一组「主 + 全量子应用」的稳定环境，版本策略明确（跟随生产 or 跟随 develop）
- E2E 覆盖重点：应用切换与路由同步、通信链路（登录态下发、事件上报）、加载失败降级——Playwright 驱动真实主子应用（E2E 基建对照「工程化」专栏，本篇聚焦微前端特有场景）
- 回归风险清单：沙箱与样式隔离的副作用（隔离改动破坏子应用运行）、公共依赖升级兼容性、路由 base 变更影响深链接与书签
- CI 分层流水线：子应用独立流水线（快、并行）+ 集成冒烟流水线（全量、发布卡点），避免一次提交触发全量构建的等待地狱
