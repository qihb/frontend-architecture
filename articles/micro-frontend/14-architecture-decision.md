# 第十四篇：微前端落地总结与架构决策

**核心要点：**

- 全系列收束到第一性原理：微前端所有方案差异，本质都是「隔离与协作的边界画在哪里」——从 iframe 的进程硬边界到 MF 的零隔离模块共享，是一条连续光谱（呼应番外篇一）
- 决策链第一步永远是「要不要微前端」：用第一篇的四维评估（团队规模、业务独立度、技术债、发布频率）先否掉伪需求，再谈选型
- 技术选型决策树：跨技术栈/存量异构 → qiankun/wujie/micro-app 系；同栈微模块共享 → Module Federation；第三方嵌入/强隔离 → iframe；内容型/SEO 场景 → 服务端组合（对应第三篇六方案）
- 渐进式落地路线：先 iframe/独立部署接入 → 编排方案收敛 → 治理规范成型 → 深度优化，反对一步到位的「微前端大跃进」（对照番外篇四的真实改造节奏）
- 常见失败模式清单：为了拆而拆、主应用长成上帝应用、通信泛滥成隐式耦合、治理规范缺位导致生态野蛮生长、把微前端当组织问题的遮羞布
- 组织匹配：拆分边界对齐团队边界才可持续，方案再好也扛不住康威定律的反向撕扯
- 演进视角：qiankun 3 原生 ESM、Rspack 生态、Web Components 与 Islands 架构的持续渗透——决策时保持「方案可替换性」，避免把基座 API 渗透进每个子应用
